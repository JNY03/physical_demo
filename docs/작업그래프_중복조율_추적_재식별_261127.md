# 작업 그래프 — 기능 간 중복 작업 조율 · 물체 추적 · 재식별 범위 (2026-11-27)

한 소스에 기능 여럿을 고르면(지정 물체 탐지의 거리 근거 + 거리 추정 + 추적 …) 같은 일을 기능마다 따로 돌리던 것을
**작업 그래프**로 묶어 한 번만 돌리고 결과를 나눈다. 계산은 `ds_resources/workgraph.py`(core, 표준 라이브러리만),
비전 프로세스 안의 나눔은 `vision/work_share.py`, 추적은 `vision/object_track.py`, 재식별 갤러리는 `vision/reid_gallery.py`.

## 1. 결과물(artifact)

레지스트리 `functions.<기능>.produces / consumes` (단계에도 적을 수 있다). 이름은 `functions.ARTIFACTS`.

| 결과물 | 뜻 | 내는 기능 (produces) | 받는 기능 (consumes) |
|---|---|---|---|
| `detections` | 상자 · 이름 · 신뢰도 | object_detect · zeroshot_detect · segmentation | object_track · single_cam_track · reid |
| `target_detections` | 판정된 검출(근거 · 판정 포함). `detections` 를 바라는 쪽도 받는다 | targeted_detect · river_detect | (위와 같음) |
| `tracks` | track_id · 궤적 | object_track · single_cam_track | multi_cam_track |
| `identities` | 전역 번호(소스 묶음) | reid · multi_cam_track | — |
| `depth` | 미터 depth 지도 · K | depth_estimate (+ targeted 의 depth 슬롯 — 내부) | targeted 거리 근거(내부 간선) |
| `embeddings` | 상자 임베딩 | 슬롯 kind embed (reid · multi_cam_track 의 embedder) | 재식별 갤러리 |
| `masks` | 분할 외곽 | segmentation · kind segment | — |
| `scene_text` | 장면 설명 | vlm | — |

부품 종류 → 결과물: detect → detections · segment → detections+masks · depth → depth · track → tracks ·
embed → embeddings · vlm → scene_text (`workgraph.KIND_ARTIFACTS`).

## 2. 중복 판정 규칙

| 규칙 | 내용 |
|---|---|
| 노드 | (소스, 단계 쪽 server/device, **모델 정체**, 매개변수 해시). 정체 = 선택지가 모델 하나만 쓰면 그 모델 (`unidepth` 선택지 → `unidepth_l`), 아니면 키. 해시 = `models.<정체>.config`(imgsz 등) |
| 같은 일 | 노드가 같으면 하나로 — `consumers` 에 기능들, `shared: true` |
| 주 노드 · 내부 | 단계의 첫 슬롯이 주 노드(기능의 produces). 둘째 슬롯(targeted 의 depth · ovd · detector …)은 그 기능 안의 일 — 내부 간선 |
| 적재 여부 | targeted 의 둘째 슬롯은 실제로 적재할 근거 모델만(`gpu_executor.estimate_mb` 의 need — 거리 끄면 depth 노드 없음) |
| fps | 노드 fps = 쓰는 기능들의 fps 최대 (기기 단계 = 단계 fps, 서버 = 소스 목표 fps, consumes 로 받는 쪽 fps 도 올린다) |
| GPU | 노드마다 한 번. `work_gpu = {total_mb, naive_mb(기능마다 따로), saved_mb}`. 비전 묶음의 GPU 어림(`estimate_mb`)도 같은 정체를 근거 쪽에서 빼고 센다(`workgraph.shared_need`) — 겹치지 않으면 옛 값 그대로 |
| dup_kind | 한 소스 · 한 쪽에서 같은 종류 결과(depth · detections …)를 **다른 정체**로 둘 이상 — 둘 다 돌리되 경고. 도메인 기능 안의 구성 arm 은 제외(거리 depth 만 포함). `align` = 모을 때 기능마다 그 슬롯에 넣을 키, `save_mb` = 그렇게 모으면 아끼는 MB |
| no_producer · param_fallback | 받을 결과를 내는 기능이 소스에 없음 · 고른 입력 기능이 그 소스에 없어 기본으로 |

**producer 고르기** (consumes → produces): 그 소스에 함께 고른 다른 기능의 주 노드 중
① 기능 매개변수(kind function — `function_params.object_track.input`)로 고른 것 ② 없으면 우선순위가 가장 높은 것
(criticality safety → mission → best_effort, 같으면 이름순). 서버 쪽 결과를 기기 쪽보다 먼저.

**프로세스를 넘는 나눔** — `controller.vision_groups` 는 소스마다 모델 조합 하나로 묶으므로 **같은 소스의 모델은 늘
한 비전 프로세스**에 있다. 그래서 같은 소스의 같은 일은 그 프로세스 안에서 나눈다(아래 3). 프로세스를 넘는 것은
소스 묶음 재식별뿐이고 Redis(`reid_embed:<소스>`)로 읽는다. 한계: 서로 다른 GPU 노드로 같은 소스를 나누는 배치는
지금 없다(GPU 노드 하나).

## 3. 비전 프로세스 안의 나눔 (vision/work_share.py)

- 장마다 `FrameWork` 하나 — 탐지 결과 `("detections", 모델)`, depth `("depth", 정체)` 를 담는다.
- **depth**: 독립 depth 모델(unidepth 선택지 · da3_metric_l)을 먼저 올리고, targeted 의 거리 근거(DepthTracker)가 같은
  가중치(정체 = (종류, 가중치 경로))면 모델을 **따로 적재하지 않고** `SharedDepthProvider` 로 그 지도를 받는다. 독립 모델이
  그 장에 돌 것이면 주기(5장)를 기다리지 않고 매 장 받는다. 먼저 부른 쪽이 재고 뒤의 쪽은 받는다.
  설정(resolution_level · fp16 · 화각 힌트)은 독립 모델 것을 쓴다.
- **검출**: 모델마다 한 번 돈다(runners 사전). 물체 추적은 FrameWork 의 검출을 받는다(탐지를 다시 돌리지 않는다).
- 증거: `vision_telemetry:<호스트>:<pid>` 의 `work` 칸 `{소스: {"depth:<모델>": {runs, reused, consumers}}}`, 로그 `work …`,
  depth 기록의 `work: {node, reused, consumers}`.

## 4. 결과 Redis 키 · 기록 (칸 추가만)

| 키 | 모양 |
|---|---|
| `vision_stream:<소스>:track` | 다른 모델 기록과 같은 필드(result · overlay · header). result: v2 머리 + `model: track`, `function: object_track`, `tracker`, `input {function, model}`, `infer_ms`, `detections[]`(+track_id), `tracks[] {track_id, label, confidence, bbox, hits, first_ts, last_ts, trajectory [[ts,cx,cy]…]}` (+ 재식별 켜면 `global_id`, `identity {function, scope, group, embedder, gallery, embed_ms}`). 저장본은 `<실행>/vision/track/` |
| `vision_stream:<소스>:<depth 모델>` | 기존 + `work` 칸 |
| `reid_embed:<소스>` | `{"result": {schema reid_embed/1, source, ts, group, embedder, items:[{track_id, label, emb(base64 float16)}]}}` (scope group) |
| `reid_identity:<묶음 · 소스>` | `{"result": {schema reid/1, group, ts, assigned:[{source, track_id, global_id, label, sim, new, ts}]}}` + hash `…:map` (`<소스>:<track_id>` → global_id, 따로 띄운 갤러리) |
| `vision_telemetry:*` | 기존 + `work` |

## 5. 재식별 범위

```
scope: source (소스 안)                         scope: group (소스 묶음 — 사람이 고른 group_sources)
 소스 A: 탐지 → 추적 → 임베딩 → 갤러리 A          소스 A: 탐지 → 추적 → 임베딩 ─┐ reid_embed:A
 (기본 매칭 features.reid = SuperPoint+LightGlue    소스 B: 탐지 → 추적 → 임베딩 ─┤ reid_embed:B
  — 사람이 고른 물체 다시 찾기 — 그대로 따로 돈다)                                 ▼
 → reid_identity:A                                  GroupGallery(묶음 하나) — 시각 맞춤 tol_s,
                                                      같은 소스 · 같은 시각 두 트랙은 다른 물체,
                                                      같은 이름 · 코사인 ≥ sim → 같은 global_id
                                                    → reid_identity:A+B
```
- 묶음의 소스가 모두 한 비전 프로세스에 있으면 갤러리도 그 안에서, 아니면 `python vision/reid_gallery.py --group A+B --sources A B`.
- 임베딩: `functions.reid.server.embedder` (기본 mobileclip_s0_cpu, CPU). 기기 embedder 슬롯은 계약만.
- 검사(`workgraph.check_params`): group 은 소스 ≥ 2, 묶음 소스 모두에 그 기능이 켜져 있어야 한다. 기본 묶음 = 그 기능을 켠 소스 전부.
- 계획 `work_reid.<기능> = {scope, group_sources, group, embedder{device, server}, gallery{node, where, redis_in, redis_out}}`.

## 6. 물체 추적 기능

`object_track` (cascade · 서버 단계 tracker 슬롯 기본 botsort, bytetrack 도 — `vision/runners/bytetrack.py`, 기기 단계는
계약만). `single_cam_track`(런처가 쓰는 옛 키)은 기기 상주판 계약으로 그대로 두었다 — 서버에서 실제로 도는 것은
`object_track`. `multi_cam_track` = object_track + 소스 묶음 재식별(scope group 고정).
켜기: 프로필 `functions.object_track.server.tracker` 또는 `function_params.object_track` (`input`, `tracker` — 슬롯이 이긴다).

## 7. 한계

- 오케스트레이터의 `--models`(비전이 돌릴 것)와 슬롯 선택(작업 그래프가 보는 것)은 아직 따로 들어온다 — 런처가 슬롯에서
  `--models` 를 만들어야 둘이 맞는다.
- depth 나눔은 같은 가중치일 때만(UniDepth · DA3). MoGe · 줄여 잰 UniDepth(`infer_long_side`)는 나누지 않는다.
- 추적 기록은 이 장에 보인 트랙만 낸다(사라진 트랙의 끝 표시 없음). 갤러리는 메모리에만 있다(재시작하면 번호가 새로).
- 소스 묶음 갤러리를 따로 띄우는 일은 오케스트레이터가 아직 하지 않는다(reid 서버 단계 image 없음).
